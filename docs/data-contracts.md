# Course data contracts

The course sites (765, sp26, and future course repos) are **data-driven**:
module pages are prose plus shortcodes that resolve keys against data files in
the site's `data/` directory — no pasted URLs, no inline due dates. This
document is the contract between those data files and the shortcodes that
consume them, so a new course repo (or next year's edition) can reproduce the
setup.

## The data files at a glance

| File | Format | Generated by | Source of truth | Consumed by (shortcode) |
|---|---|---|---|---|
| `data/assignments.yaml` **or** `data/assigns.yaml` | YAML map | `assigns.py` | Canvas assignments | `assign-link`, `assign-linkonly` |
| `data/readings.yaml` | YAML map | `seatable-to-html.py` | SeaTable DB `765-Readings` (+ `files.yaml`) | `reading` |
| `data/files.yaml` | YAML map | `files.py` | Canvas files+folders | Canvas-file link shortcode (in course repos); also the `cfile` lookup source for `seatable-to-html.py` |
| `data/modules.toml` | TOML array | hand-authored | — | `moddesc`, `modname`, `modlo` |
| `assets/pages.csv` **or** `data/pages.yaml` | CSV / YAML map | hand-authored | — | `page` |

The generators live in the **`uwgraphics/SimpleCourseTools`** repo (Python).
They are *not* run by Hugo — they are run by hand (or a course-maintenance
routine) to (re)produce the YAML, which is then committed into the site's
`data/` directory. See "Regenerating the data" below.

> **Note on the sp26 fork.** The sp26 overlay renamed `assigns.yaml` →
> `assignments.yaml` and improved the shortcode error messages (they include
> `.Position`). The unified theme's `assign-link`/`assign-linkonly` accept
> **either** file name — they use whichever of `data/assignments.yaml` or
> `data/assigns.yaml` is present. Providing **both** is a build error (so a
> rename can't silently leave a stale copy behind). There is no deprecation
> warning; both names are first-class. Schema is otherwise identical.

**Status (Phase 4).** All the consumer shortcodes named below now live in the
**theme** (`559Theme/layouts/_shortcodes/`): `assign-link`, `assign-linkonly`,
`reading`, `moddesc`, `modlo`, `modname`, `page`. A course repo supplies only
config + data + content + snippets. The per-course copies (765's
`layouts/shortcodes/`, the sp26 mixin overlay) are being retired.

## `assigns.yaml` — Canvas assignments

Generated by `SimpleCourseTools/assigns.py` (`makeAssignmentsYAML`) from the
Canvas `assignments` API.

**Key:** a slug derived from the assignment name — `slugify(name.split(":")[0])`
(lowercased; ` - `, spaces, `?` normalized). Example key: `design-exercise-1-1`.

**Value (one map per assignment):**

```yaml
design-exercise-1-1:
  name:        # full Canvas assignment name (e.g. "Design Exercise 1-1: Foo")
  shortname:   # name before the first ":"  (e.g. "Design Exercise 1-1")
  url:         # Canvas html_url for the assignment
  due:         # full datetime string, e.g. "2025-09-08 17:00:00-05:00"
  due_string:  # short human form, e.g. "Mon, Sep 08"
  lock:        # full datetime string (falls back to due if no lock date)
  lock_string: # short human form
```

**Consumers.** `assign-link` and `assign-linkonly`:

- `{{< assign-link "design-exercise-1-1" >}}` → link to the Canvas assignment,
  text = `name`.
- Second positional arg is a space-separated set of modifier words:
  `short` (use `shortname`), `due` (append `(due <due_string>)`).
- Third positional arg (optional) is a page path: the link then points at that
  page, and a separate "Canvas" link is emitted for the assignment.
- Unknown key → build error, **except** the sentinel key `TBD`, which renders
  the literal text `TBD` (used for not-yet-created assignments).

## `readings.yaml` — reading list / bibliography

Generated by `SimpleCourseTools/seatable-to-html.py` from a **SeaTable** cloud
database (table `765-Readings`). SeaTable is the human-curated source of truth;
the script renders each row into a pre-formatted HTML citation string. It reads
`files.yaml` to turn a row's `cfile` into a Canvas file link.

**Key:** the SeaTable `Key` column (e.g. `CM84`, `VAD2`, `eyeshaveit`).

**Value:** a single pre-rendered **HTML string** (the citation). The map is
flat — `{ Key: "<html>" }`. It is **not** typed; there are no
required/optional fields in the data (see the `reading` consumer for typing).

The citation string is assembled from these SeaTable columns, in order, each
appended only if present:

| SeaTable column | Rendered as |
|---|---|
| `Authors` | `Authors. ` (escaped) |
| `Title` | `<b>Title</b>. ` (markdown-rendered) |
| `Subtitle` | `Subtitle. ` (markdown) |
| `citation` | `citation. ` (markdown) |
| `cfile` | `<a …>(Canvas File)</a>` — URL is `files.yaml[cfile].url_nodl` |
| `doi` | `<a …>(doi)</a>` |
| `pdf` | `<a …>(web pdf)</a>` |
| `url (web page)` | `<a …>(url)</a>` |
| `video` | `<a …>(video)</a>` |
| `library` | `<a …>(UW Library)</a>` |
| `summary` | `<a …>(Summary)</a>` |

A `cfile` value that is not a key in `files.yaml` renders `(BAD cfile)` and
prints a warning — so `readings.yaml` generation **depends on a current
`files.yaml`**. The script also emits a `readings.html` preview listing.

**Consumer.** `reading`:

```text
{{< reading "CM84" >}}              citation only
{{< reading "CM84" "required" >}}   with a colored type badge
```

The **type** (required / optional / alternate / recommended / summary) is the
*second positional argument at the call site* — it is not stored in
`readings.yaml`. `reading` renders a colored `(required)` etc. prefix, then the
citation HTML. Unknown key → build error.

## `files.yaml` — Canvas file index

Generated by `SimpleCourseTools/files.py` from the Canvas `files` + `folders`
APIs. First line is a provenance comment: `# Fetched from Canvas <date>`.

**Key:** the file's `filename` (e.g. `01-InfoVis-CardMackinlaySchneid-Chap1.pdf`).

**Value (one map per file):**

```yaml
01-InfoVis-CardMackinlaySchneid-Chap1.pdf:
  url:         # full download URL, incl. ?download_frd=1&verifier=<token>
  url_nodl:    # url with "download?…" stripped → clean /files/<id>/
  filename:    # same as the key
  size:        # bytes
  size_str:    # e.g. "77.4mb"
  updated:     # ISO datetime
  folder:      # folder name (or "/")
  folder_path: # full folder path (or "/")
```

Files in `ignoreFolders` (hardcoded default `["LectureNotes-2021"]`) are
skipped; duplicate filenames print a warning (last one wins).

**Consumers.** Two:

1. Build-time input to `seatable-to-html.py` (the `cfile` → `url_nodl` lookup
   for readings).
2. A **Canvas-file link shortcode used in some course repositories** — it
   resolves a filename to its Canvas URL via this map. (None of the four sites
   currently in this workspace reference it, and it is not yet in this theme;
   it lives in other course repos and is a candidate to promote into the theme.
   It is a live runtime data file, not merely a build artifact.)

> **Repo-hygiene caveat.** `files.yaml`'s `url` field embeds volatile Canvas
> **verifier tokens**. Committing the file into a site repo bakes those tokens
> into git history. Prefer `url_nodl` at the consumer, and consider gitignoring
> `files.yaml` (or scrubbing the `url`/verifier field) in site repos — keeping
> only what the runtime shortcode actually needs.

## `modules.toml` — module metadata

Hand-authored (no generator found). A TOML array of `[[module]]` tables.

```toml
[[module]]
id = 1
name = "Visualization and Effectiveness"
description = """ …markdown… """
outcomes = [ "…", "…" ]
```

**Consumers.** `moddesc`, `modname`, `modlo` all take the module **id** as the
first positional arg and look it up with `index hugo.Data.modules.module <id>`.

> **Gotcha — id must equal array position.** The lookup indexes the `module`
> array *by position*, so a module's `id` must match its index in the file
> (id 0 first, id 1 second, …). The example `id = 0` module is the placeholder
> at position 0. Reordering or gapping ids silently returns the wrong module.

- `modname <id>` → `name` (safeHTML)
- `moddesc <id>` → `<p>` of `description` (markdown)
- `modlo <id>` → `<ol>` of `outcomes` (each markdown)
- Unknown id → build error.

## `pages.yaml` / `pages.csv` — service/quick links

Hand-authored (no generator). Two interchangeable formats are accepted; a site
supplies **exactly one** (providing both is a build error — see below):

- **`assets/pages.csv`** (primary) — a CSV with a header row. Columns
  `key,name,url` are required; an optional `heading` column is allowed (it is
  not used by the `page` shortcode, but groups entries for humans / other
  widgets). Read at build time via `resources.Get "pages.csv"`.
- **`data/pages.yaml`** (fallback) — a flat YAML map, key → `{url, name}`.

```yaml
# data/pages.yaml
regrade-form:
  url: https://forms.gle/…
  name: "Regrade Request Form"
```

```csv
# assets/pages.csv
heading,key,name,url
Forms,regrade-form,Regrade Request Form,https://forms.gle/…
```

**Consumer.** `page`:

```text
{{< page "regrade-form" >}}            link, text = entry's name
{{< page "regrade-form" "alt text" >}} link with custom text
```

Links open in a new tab (`target="_blank"`). The shortcode reads `pages.csv` if
present, otherwise `pages.yaml`. **If both exist it is a build error** — no
silent precedence, and no deprecation warning (both formats are first-class).
Unknown key → build error.

## Regenerating the data (SimpleCourseTools)

The Canvas-backed files are produced by Python scripts in
`uwgraphics/SimpleCourseTools`, driven by `canvas.py` + a **`.canvas.yaml`**
config that holds the Canvas server, course id, staff ids, and an API token.

```sh
python files.py    # → files.yaml   (run first; readings depends on it)
python assigns.py  # → assigns.yaml
python seatable-to-html.py   # → readings.yaml (+ readings.html) from SeaTable
```

Then copy the generated YAML into the course site's `data/` directory.
Regeneration order matters: `files.yaml` must be current before
`seatable-to-html.py` runs (bad `cfile` refs otherwise).

**Credentials / secrets:**

- `.canvas.yaml` (Canvas API token, course id, staff ids) is **gitignored** in
  SimpleCourseTools and must never be committed — a Canvas token grants access
  to student data. (Verified: it is not tracked and not in git history.)
- The SeaTable token in `seatable-to-html.py` is a deliberate, read-only,
  single-database token that the author has chosen to keep in the source.

## Shortcode conventions (for promoting these into the theme)

All the course shortcodes follow the same shape and should keep it when
promoted into the theme (Phase 4):

- Data access via `index hugo.Data.<file> <key>` (or `.<subkey>`).
- **Fail fast**: an unknown key is a build `errorf` that names the key and the
  page (`.Page.File`) — adopt sp26's version, which also includes `.Position`.
- Sentinel escape hatches where the workflow needs them (`assign-link`'s `TBD`).
- Historically these lived per-course; several source comments literally ask
  "not sure why this isn't in the theme" — promoting them (with this documented
  contract) is the point of Phase 4, so 765-26 and future courses supply only
  config + data + content + snippets.
