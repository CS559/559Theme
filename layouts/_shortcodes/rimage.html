{{/* rimage — the preferred way to include an image. Supports captions, attributions, and REAL resizing. Works for SVG and for PNG/JPG/GIF. This takes the place of both resource-image (resource lookup + resizing) and figure (captions), so the caption is sized to the width of the image (captions look wrong otherwise). Unlike resource-image it uses WIDTH, not SIZE — we need the width for the figure/caption sizing. Resizing behaviour (raster: real derivatives via .Fit; SVG: vector, never re-encoded, width only ever affects CSS/layout, never the file itself): - width is a number (px) -> raster: a copy Fit to that width is generated and shown; figure links to the original. SVG: no derivative (can't re-encode a vector); the figure's CSS width is set to the literal px value, and it links to the original (since it's being shown smaller than the file's own size). - width is a percent -> raster: the file is Fit to (percent x an assumed content-column width, default 800px, set params.imageColumnWidth to tune) and a build warning notes it is approximate; the figure CSS still uses the literal % so layout stays fluid. SVG: the figure's CSS width is set to the literal percent; links to the original. - width="native" -> raster: no resizing; the image is shown at its native pixel size and the figure is sized to match. SVG: no CSS width is imposed at all — the figure shrinks to hug whatever intrinsic size the SVG file itself declares (still capped at 100% of the content column like any image, so it can't overflow the page). Either way, native means "shown exactly as the file declares itself", so there's no zoom link (linking to itself would be a no-op). - .Fit never upscales, and we skip generating a raster copy entirely when the target is >= the image's native width, so small raster images are never blown up and never get a pointless "full size" link.
